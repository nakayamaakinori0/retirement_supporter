# 退職届（願）生成時のインタースティシャル広告

- Issue: #22
- Status: Approved

## 背景 / 目的

アプリの収益化。退職届・退職願のPDF生成は、このアプリで最も価値のある操作であり、
利用者が「対価を払ってもよい」と感じやすい唯一の場面でもある。ここに全画面広告を1回だけ差し込む。

一方でこの画面は、利用者にとって心理的に重い場面でもある。
**広告のために本来の機能が止まることは絶対に避ける**。これを最優先の制約とする。

## スコープ

### やること

- EAS Build を導入する（`eas.json`、`expo-dev-client`）
- `react-native-google-mobile-ads` を導入する
- 確認画面の「生成」タップ時に、PDFを出す前にインタースティシャル広告を1回表示する
- 広告の読み込み失敗・タイムアウト時は、広告なしでPDF生成を続行する
- iOS の App Tracking Transparency（ATT）に対応する
- 開発時はGoogleのテスト広告IDを使い、本番ビルドでのみ実IDを使う

### やらないこと

- Android 対応（AdMob のアプリ登録が iOS のみのため。実装は差し替え可能な形にする）
- バナー広告、リワード広告
- 広告除去の課金（将来的な選択肢としては残す）
- 広告表示回数の上限やクールダウンの制御（初版は生成ごとに1回）

## 仕様

### 広告の表示タイミング

確認画面（`app/form-retirement-letter-confirm.tsx`）の「生成」ボタンをタップした直後、
PDFを生成・共有する前に1回だけ全画面広告を表示する。広告を閉じたらPDF生成に進む。

```
「生成」タップ
    ↓
広告の読み込み（最大 5 秒待つ）
    ↓                    ↓
 読み込めた            失敗 / タイムアウト
    ↓                    ↓
 広告を表示                │
    ↓                    │
 広告を閉じた ──────────────┤
                          ↓
                    PDF生成 → 共有
```

### 広告が出せない場合の扱い

以下はすべて「広告なしでPDF生成を続行」とし、利用者にエラーを見せない。

- 広告の読み込みに失敗した（在庫なし、ネットワーク不通、設定不備）
- 読み込みが 5 秒以内に終わらなかった
- 広告SDKの初期化が終わっていない

広告が出ないこと自体は利用者にとって不利益ではないため、通知や再試行はしない。

### 広告IDの出し分け

```ts
const interstitialAdUnitId = __DEV__
  ? TestIds.INTERSTITIAL          // SDK が提供するテストID
  : 'ca-app-pub-8035028352595890/6870296100';
```

開発中に実広告を読み込むと、AdMob のポリシー上「無効なトラフィック」と判定され
アカウント停止のリスクがあるため、`__DEV__` で必ず分岐する。

### App Tracking Transparency（iOS）

`expo-tracking-transparency` を導入し、アプリ起動後に一度だけ同意を求める。

- 同意が得られなくても広告は表示する（非パーソナライズ広告になる）
- `NSUserTrackingUsageDescription` を `app.json` に設定する
- ATT のプロンプトを出さずに IDFA へアクセスすると、App Store の審査でリジェクトされる

### ビルド構成の変更

広告SDKはネイティブコードを含むため、**Expo Go では動作しなくなる**。

- `expo-dev-client` を導入し、開発は開発ビルドで行う
- `eas.json` を追加し、`development` / `preview` / `production` のプロファイルを定義する
- `app.json` に `react-native-google-mobile-ads` の config plugin とアプリIDを設定する
- `app.json` の `version` を `2.0.0` に上げる

## エッジケース

- **広告表示中にアプリがバックグラウンドに入る** — SDK の挙動に任せ、閉じられた時点でPDF生成に進む
- **読み込みは間に合ったが利用者が広告を長く見ている** — 5秒のタイムアウトは
  「読み込み」の上限であり、表示フェーズには適用しない。読み込み完了時点で
  タイマーを止める（止め忘れると広告の裏でPDF生成と共有シートが走る）
- **「生成」の連打** — `useRef` のフラグで二重実行を防ぐ。`useState` は同期的に
  反映されず、同じレンダーのクロージャで複数回押されるとすり抜けるため使わない。
  広告の読み込み中もこのガードを効かせる
- **広告を閉じた直後にPDF生成が失敗** — 広告とは独立した既存の問題（#19）。本 spec では扱わない
- **同じ画面で複数回生成する** — 生成のたびに広告を読み込み直す（インタースティシャルは1回表示したら再利用できない）
- **CLOSED も ERROR も来ないまま固まる** — SDKがイベントを落とす、広告表示中に
  アプリが復元される等で起こりうる。放置するとPDFが永久に生成されず、生成ボタンも
  無効のままになるため、表示フェーズにも十分に長い上限（120秒）を設けて必ず解決させる
- **SDKの初期化前に生成が押される** — 初期化を待ってから広告を要求する。
  待たないと初回の広告要求が必ず失敗し、初回生成の収益を取りこぼす

## 受け入れ条件

- [x] 「生成」タップ後、PDFが出る前に全画面広告が表示される
- [x] 広告を閉じるとPDFの生成・共有に進む
- [x] 広告の読み込みに失敗しても、PDFの生成・共有が完了する
- [x] 広告の読み込みが 5 秒を超えても、PDFの生成・共有が完了する
- [x] 開発ビルドではテスト広告が表示される（実広告を読み込まない）
- [x] `npm run typecheck` / `npm run lint` / `npm test` が通る

## テスト方針

`react-native-google-mobile-ads` をモックし、広告の状態ごとの分岐をユニットテストで固定する。

- 広告が読み込めた場合、広告を表示してからPDF生成に進む
- 広告の読み込みに失敗した場合、PDF生成に進む
- タイムアウトした場合、PDF生成に進む
- 広告の状態にかかわらず、PDF生成が必ず1回呼ばれる

実機での広告表示は自動テストでは検証できないため、開発ビルドでの手動確認とする。
