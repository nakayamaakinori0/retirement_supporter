# 退職までにやることリスト

- Issue: #13
- Status: Approved

## 背景 / 目的

退職は多くの人にとって初めての経験で、「何を、どの順番で、どうやればいいのか」が分からない。
このアプリは退職日までのカウントダウンと退職届の作成を提供しているが、その間にある実務（意思表示、引き継ぎ、保険や年金の切り替えなど）は利用者が自力で調べるしかない。

チェックリストで全体像と進捗を可視化し、各項目に「具体的にどうやればいいか」の説明を添えることで、調べる手間と抜け漏れの不安をなくす。

## スコープ

### やること

- 3つ目のタブとして「やることリスト」を追加する
- 退職手続きの定番項目を固定リストとしてアプリに持つ
- 各項目をチェックでき、チェック状態を端末に永続化する
- 各項目をタップするとアコーディオンで「やり方の説明」が開く
- 画面上部にプログレスバーと達成数を表示する

### やらないこと

- ユーザーによる項目の追加・編集・削除（固定リストのみ)
- 退職日からの逆算による期限表示やリマインド通知
- 項目の並び替え
- サーバー同期（端末内で完結する）

## 仕様

### 画面 / UI

タブ構成（左から）:

1. 退職届生成フォーム
2. ホーム（退職日数カウントダウン）
3. **やることリスト** ← 追加

画面構成:

```
┌─────────────────────────────┐
│  3/12 完了                   │  ← 達成数
│  ████████░░░░░░░░░░░░        │  ← プログレスバー
├─────────────────────────────┤
│  ☑ 就業規則で退職ルールを確認  │  ← チェック済みは打ち消し線
│  ☑ 退職の意思を直属の上司に伝える│
│  ☐ 退職届を提出する        ▼ │  ← タップで開閉
│    ┌───────────────────────┐ │
│    │ 説明文（アコーディオン）  │ │
│    └───────────────────────┘ │
│  ☐ 引き継ぎ資料を作成する     │
│  ...                        │
└─────────────────────────────┘
```

- チェックボックスのタップ = 完了状態のトグル
- 行（チェックボックス以外）のタップ = 説明の開閉
- 開閉は同時に複数開けてよい（アコーディオンの排他制御はしない）
- 配色は `src/constants/colors.ts` の `Colors` を使う

### 振る舞い

1. タブを開くと、永続化されたチェック状態を読み込んで復元する
2. 項目をチェックすると即座に永続化され、プログレスバーと達成数が更新される
3. 全項目を完了すると、リスト上部に完了メッセージを表示する
4. 説明の開閉状態は永続化しない（画面を離れると閉じた状態に戻る）

### データ / 状態

**項目の定義** — `src/constants/todoItems.ts` に定数として持つ。

```ts
export type TodoItem = {
  id: string;        // 永続化のキーになるため変更しない
  title: string;     // リストに表示する見出し
  description: string; // アコーディオンで開く「やり方」の説明
};
```

**チェック状態** — AsyncStorage のキー `todoCompletedIds` に、完了した項目の `id` の配列を JSON で保存する。

完了状態ではなく「完了した id の集合」を持つことで、項目を後から追加・削除しても既存の状態が壊れない。
定数側から消えた id が保存されていても無視する。

### 項目一覧（初版）

| # | id | 見出し |
| --- | --- | --- |
| 1 | `check-rules` | 就業規則で退職のルールを確認する |
| 2 | `decide-date` | 退職日を決める |
| 3 | `tell-boss` | 退職の意思を直属の上司に伝える |
| 4 | `submit-letter` | 退職届を提出する |
| 5 | `handover` | 引き継ぎ資料を作成する |
| 6 | `use-paid-leave` | 有給休暇の残日数を確認して消化する |
| 7 | `return-items` | 会社からの貸与品を返却する |
| 8 | `receive-documents` | 会社から受け取る書類を確認する |
| 9 | `health-insurance` | 健康保険の切り替えを決める |
| 10 | `pension` | 年金の切り替え手続きをする |
| 11 | `unemployment-benefit` | 失業給付の手続きをする |

説明文は各項目 100〜200 字程度で、「いつ・どこで・何を」が分かる粒度で書く。
制度に関わる項目（9〜12）は、金額や期限の断定を避け、公的窓口で確認するよう促す文言にする。

## エッジケース

- **保存データが壊れている / パースできない** — 空配列として扱い、アプリを落とさない
- **定数から削除された id が保存されている** — 無視する（達成数の分母は常に現在の項目数）
- **読み込み中** — チェック状態が確定するまではチェックを操作できないようにし、未完了状態がちらつかないようにする
- **項目を後から追加した場合** — 追加分は未完了として扱われ、分母が増える

- [x] 項目をチェックするとプログレスバーと達成数が更新される

- [x] 全項目を完了すると完了メッセージが表示される

- [x] `npm run typecheck` / `npm run lint` / `npm test` が通る

## テスト方針

`src/components/__tests__/TodoList.test.tsx` を追加する。

- 初期表示で全項目が描画される
- チェックすると達成数が増える
- チェック状態が AsyncStorage に保存される
- 保存済みの状態を復元する
- 壊れた保存データでもクラッシュしない
- タップで説明が開閉する

AsyncStorage は既存の `jest.setup.js` のモックを使う。
日付に依存しないため、タイムゾーンの影響を受けない。
